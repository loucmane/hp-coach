## RULE 11 (NEW — from las-b17-001, demonstrated blind-solvable 4/4):
**No cross-question lexical or conceptual bridges.** After drafting, take
each question's OPTION SET alone (no passage, no stems) and check every
other question's option set for shared content words or paraphrase-level
concept repeats. A word family that appears in one question's KEY and
another question's options (batch17's 'glöd' chain: q2 "glödde kvar" ↔ q3
"släcka glöden" ↔ q4) lets a blind solver corroborate keys across the
sheet — a fresh G-STEM reviewer walked batch17's las-b17-001 to ALL FOUR
keys this way. Mechanical self-check required in NOTES: list every content
lemma appearing in ≥2 questions' options; justify each survivor (function
words and the passage's unavoidable topic word are exempt; mechanism words
are not).

## RULE 12 (NEW — from elf-b17-003): **The stem must not entail any option.**
Read each stem by itself and write down what it gives away. A stem that
semantically entails an option's claim ("the pin the leaf STANDS ON" ⇒
"carries the leaf's weight") hands the blind solver a pick even when it
lands on a distractor — that's a misfire channel we no longer ship
knowingly. Prefer neutral referential stems ("Vad sägs om X?" where X is
named without predicating anything contested about it).

## RULE 13 (NEW — style-tell clustering): never let exactly one option per
question be the qualified / two-factor / hedged one when its siblings are
sweeping — the M-FORM absolutizer family is now COMPLETE (alltid/aldrig/
samtliga/alla/allt/varje/enbart/endast/ingen/inget/inga/helt/omöjligt/
garanterat/ingenting/ingenstans/uteslutande + EN counterparts incl.
nothing, nobody, "no one", nowhere, everyone, everybody, everything) and
G-STEM hunts the residue. Per rule 10: on some questions the KEY is the

## RULE 15 (NEW — from las-b19-003, measured as a PAIR at stage 11):
**In a two-question LÄS set, never pair a mechanism-inventory question with
a stance question over the same hypothesis space.** Measured separately the
set is unremarkable — Q1 alone ≈ 70 % stems-only, Q2 alone ≈ 55–60 %, which
is why every gate and the meta-review filed it at note. Measured as a pair
it reads to **≈ 80 % with the passage unopened**: Q1's options are an
inventory that reprints the essay's hypothesis space, so they NAME the
candidate mechanisms; Q2's options are stances over that same space, so Q2
inherits whatever Q1 discloses and becomes the easier of the two once Q1 has
been read — the reverse of the intended dependency direction. If one
question enumerates candidate mechanisms, **the other must turn on
something outside that enumeration** (a detail, a scope limit, a
method-versus-result contrast — anything whose option field is not the
hypothesis list). State the pair check in NOTES: give the joint stems-only
floor, not two separate per-question floors.

## RULE 21 (NEW — how RULE 17 and law 16 interact; write it down once):

**An ordinary name is exempt from law 16's blanket "any real bearer rejects"
— but only under three conditions, and only for the ordinary figure.** RULE
17 requires at least one wholly ordinary, unremarkable name per unit. Law 16
as the brief states it rejects any name with a real bearer. An ordinary name
has ordinary bearers BY CONSTRUCTION, so the two cannot both be satisfied
literally, and no amount of searching will make them. This is not a defect
in either rule and it is not a defect in the check; it is the price of RULE
17, and it has to be paid explicitly rather than discovered again.

Three batch20 generators hit the collision independently and independently
invented the same resolution — elf-b20-001 in a `law_tensions` field,
elf-b20-002 in section (8) of its search log, elf-b20-003 in a
`rule17_and_rule16_tension_note` — with las-b20-001 and las-b20-003 arriving
at the same practice for their Swedish ordinary figures. Three generators
solving the same problem three times is the brief's failure, not theirs.
Here is the resolution, so the next one does not have to invent it:

**The ordinary figure is exempt from law 16's blanket bearer test ONLY when
all three of these hold.**

- **(a) No NOTABLE bearer.** Zero on the encyclopaedia index for the exact
  full pair, CHECKED in a control-passing session, not assumed. Evidence for
  why it is checked: elf-b20-003 dropped the ordinary name *Helen Jeavons*
  after the web index returned a notable bearer (an NRA World Action Pistol
  Ladies Champion), and las-b20-002 dropped *Kjell Sundström* on
  sv.wikipedia totalhits=14 with an article titled exactly that. An ordinary
  name with a notable bearer is a WORSE ordinary name than one with only
  private bearers.
- **(b) No bearer in the unit's own subject domain.** This leg has teeth and
  is the one that actually rejects names: elf-b20-001 dropped an otherwise
  clean ordinary pair, *Trevor Dodd* — encyclopaedia zero for the pair, so
  leg (a) passed — because the web index returned a UK freight forwarder
  among its bearers, and the unit is a ferry-operation and
  transport-statistics piece. Diffuse private bearers scattered across
  unrelated fields are the intended cost of RULE 17; a bearer standing in
  the unit's own trade is a collision. Name the domain, run the domain query
  explicitly, and record it, the same way a coinage's probes are recorded.
- **(c) The ordinary figure is given no quoted words and no attributed act.**
  It may be a signatory, a ledger entry, a wage-book line, a name on a
  seating plan, a walk-on. It may not speak, and it may not be the source of
  a contested claim. The speaking and the claim-making go to the DISTINCTIVE
  COINAGES, which stay under law 16's full strictness with the whole RULE 16
  distance burden on top. batch20 shipped this split cleanly: *Knut
  Olofsson* is an 1858 signatory and is not quoted; *Hildur Jansson* stands
  in a wage book and the unit says in terms that the colour instructions are
  unsigned and that no card can be tied to a particular hand; *Alison
  Hebden* carries a byline while the invented *Hoskadale* carries the quoted
  skipper's voice — "the riskier role, the person with invented words in his
  mouth, was given to the coinage, not to the ordinary name."

**The point, stated plainly: a name that identifies nobody in particular
cannot put words in a real person's mouth.** That is the whole justification
for the exemption, and it is also its limit. The moment the ordinary figure
speaks or asserts, the name stops identifying nobody in particular and law
16 applies to it with full force — at which point it is no longer serving
RULE 17 either. Do not negotiate around this by making the ordinary name
slightly unusual: a half-coined name gets the worst of both rules, the
texture RULE 17 wants and the exposure law 16 guards against.

`rule17_and_rule16_tension_note`, or the equivalent) so a gate SEES the
split rather than having to infer it: name the ordinary figure, name the

the ordinary name including the domain query actually run.

### The G-STEM option-form checklist (batch20 r1: 3 pass / 9 flag / 8 KILL)

Batch20's units passed G-KEY 40/0 on the first round and still lost eight targets to
G-STEM, every one on option-set FORM. Before committing any option set, cover the
passage and try to rank the four options on wording alone. If you beat 1-in-4 by any
of these routes, rebuild:

1. **Absolutizer/hedge triage.** The key is the only hedged option, or the only one
   without an absolutizer, or one distractor stacks "only/every/exactly" so it dies
   for free. Fix: balance hedging across the set; on some questions make the KEY the
   confident claim and let a distractor over-hedge (law 10).
2. **Contradictory dyad.** Two options are contradictories on one variable (did / did
   not; steeper / gentler; settled / cannot support). A test-wise solver keeps the
   pair and drops the rest — 50% for free — and the key is almost always in the pair.
   Fix: put each option on a DIFFERENT variable (elf-b20-004 did this and was the only
   unit G-STEM passed clean).
3. **Mirrored twin.** A distractor is the key with its causal arrow reversed, and the
   mirror is physically impossible (nutrients do not oxygenate water). A mirror is only
   ever built around a true forward direction, so its presence advertises the key.
   Fix: if you use reversed causality, the reversed version must be plausible without
   the passage, and it must not be the only pair in the set.
4. **Main-idea scope triage.** For "what is the passage mainly about": A too narrow,
   B too broad, C off-topic, D the summary — and D is also the only option written as
   a summary tricolon. Fix: all four options the same SHAPE; discriminate on content.
5. **Stem announces the answer's shape.** "vid jämförelsen" guarantees a comparative
   finding and only one option is comparative; "kan dra för slutsats" matches the only
   option carrying "sannolikt"; "implied" favours the only inference-shaped option.

## RULE 26 (NEW — evidence hygiene: a number is a claim, and a correction is a claim twice over)

RULE 22 said write only what a script can re-derive. Batch22's four rounds show where that still
leaks. Every leak below was found by a gate, in a unit whose *content* was fine — this is a

- **State the population and the glob inline with every distance figure.** Four different
  populations were in play all batch — the bank (`candidates-final` + `batch18..21/candidates`,

  and whole-file scope — and scope drift between them produced false figures in three units.
  A minimum without its population is not evidence. Write `Bangatan ~ Bengta 3 (bank, 142 files,
  glob …)`, not `Bangatan 6`.
- **Declare the case policy on every Levenshtein screen, and casefold.** Batch22 spent two rounds
  on a dispute in which one round measured `Ruddiforth`~`Uniform` exact-case (6) and the next
  measured it casefolded (5); each accused the other of error and both were right. A
  confusability screen should not see letter case. Casefold, and say so in the field.
- **Emit counts from the same script that emits the minima**, with the tokenizer and scope stated,
  or omit the count. Hand-enumerated token counts produced FIVE different figures for one
  population across batch22's rounds (2258 / 2241 / 2212 / 2289 / 2161). No bar reads any of them.
- **The correction protocol.** When a round corrects an earlier number it states, in the field:
  the old value, the new value, the scope, and the code path — and it re-runs the screen at the
  stated scope. A correction is not exempt from being a claim. In batch22 a "correction" replaced
  a correct figure with a wrong one while announcing the fix, and another overwrote a correct bank
  minimum with a sibling minimum. **Re-derive; never assert from an earlier round's list.**
- **Never accuse an earlier round of error without reproducing both figures.** If they differ,
  suspect an undeclared parameter before suspecting arithmetic.
- **Evidence prose is copy, and it goes through the n-gram screen like any other string.** When a
  rule prescribes a form of words — a correction protocol with four named parameters, a two-scope
  partition, a staleness stamp — every unit writes something close to the same paragraph, and
  agents read each other's fields. A batch22 repair agent caught its own first correction block
  lifting a sibling's prose at 21 maximal runs, including a 14-token and a 13-token lift, and
  rewrote it down to a longest run of 9 while keeping all four named parameters.
  **Scope, added after batch23 measured 200 shared runs of 8+ tokens across seven units' metadata:**
  this screen targets borrowed FINDINGS and FIGURES, not the shared vocabulary of a protocol this
  brief itself prescribes. When a rule dictates that every unit state an old value, a new value, a
  scope and a code path, every unit will write similar sentences, and that is compliance. What must
  not be shared is a conclusion, a distance, a census, or a claim about the corpus that one unit
  derived and another copied.
- **No blanket negatives** (RULE 22 carry-over, still being violated): "X does not occur anywhere
  under `batches/`" was false in two batch22 units by the time the round ended, because sibling
  workers had quoted the name into their own sweep transcripts. Path-partitioned positive claims
  only, and a sweep that reads sibling *metadata* is measuring the wrong thing: read the five
  student-facing paths and say that is what you read.
- **The sibling-sweep field holds a script path, a digest list and the emitted minima — and no
  prose.** Coordinator ruling, 2026-09-15, on an escalation from batch22's arena unit, whose sweep
  field failed to hold a reproducible figure for two consecutive rounds. Prose claims in that field
  went false three ways in one batch: they named a byline that had been withdrawn, they asserted
  absences that sibling workers falsified while the round was still running, and they gave reasons
  for minima that did not survive re-derivation. The field's job is to let a reader re-run the
  screen, not to argue its conclusion. Anything you want to *say* about the result goes in the
  repair-log entry, where it is dated and scoped.
- **A structural field may be a list or a dict, and your extractor must handle both.** Batch22's
  arena unit caught its own sweep returning zero names for one sibling because that sibling ships
  `named_figures` as a list of dicts; the same pass also dropped a name that occurs only in the
  Swedish genitive. Both would have produced a confident, wrong, "corrected" count. Test your
  extractor against every sibling before you trust its output.
- **A sibling-dependent figure is stamped with the sibling bytes it speaks for** (sha256 + mtime
  per sibling, timestamped) and is derived in the last step before writing. Siblings are being
  repaired concurrently; a sweep written mid-round speaks for bytes that no longer exist. A
  V-FINAL sweep is owed once the batch stops moving, and no in-round sweep replaces it.

## RULE 27 (NEW — the repair round is itself a defect source; budget for it)

Measured across batch22's three repair rounds, by unit, by gate:

| round | strings changed | defects introduced | share in the worst unit |
|---|---|---|---|
| fleet-repair-1 | — | 14 | 8 of 14 |
| fleet-repair-2 | — | 17 | 10 of 17 |
| fleet-repair-3 | 29 in LÄS, 2 in ELF | 14 in LÄS, 3 in ELF | 8 of 14 |

Round three was run under an explicit fewest-strings instruction and the rate did **not** fall: the
Swedish lane changed 29 strings and introduced 14 defects, flat against round two's 17. What the
data actually shows is that the rate tracks the *unit*, not the volume — one unit produced 8, 10
and 8 of each round's total, while a unit that changed two strings produced three defects and a
unit that changed none produced none. Do not expect a smaller round to be a safer one. Binding:

- **The defect rate tracks WHOLE-FIELD REPLACEMENT, not the number of strings changed.** Batch23's
  first repair round is the clean experiment: 10 new defects out of only 19 student-facing edits,
  and **9 of the 10 came from the two units that replaced an entire rationale field, while the unit
  that edited only fragments produced none.** A fragment edit is bounded — you change a clause and
  the sentences around it stay proven. Authoring a field afresh is generation, and it carries
  generation's defect rate. So: edit the clause, not the field. If a field genuinely has to be
  rewritten whole, treat it as new copy and screen it as new copy, including against the findings
  already filed on the text you are replacing.
- **The prose freeze does not cover a field you are authoring anew.** "Repair correctness, carry
  prose quality" is right for text you are leaving alone, and batch23's own injection rate vindicates
  it. It does not license re-typing a flagged clause into a field you are writing from scratch. A
  clause typed into a newly authored field is *written*, not carried, and the marginal cost of
  getting it right there is nil against the cost of opening a fresh string. Four batch23 clauses were
  carried this way and a gate correctly overturned the rejection for exactly those four while
  upholding it everywhere the repair left text untouched.
- **Rationale prose does not converge under repair. Budget ONE prose pass per unit, then freeze
  the layer.** Measured over batch22's five rounds, new defects introduced in rationale prose ran
  14, 17, 17, 11 — while each round also fixed a comparable number. The population of defects is
  roughly stationary: repairing a limb rewrites it, and a rewritten limb is new copy with a new
  chance of a stutter, a lemma cluster or a pronoun reaching too far. None of these defects ever
  affected answerability; across the whole batch, every key and every distractor verified clean
  while the prose oscillated. So: run one prose pass, fix what it finds, and then treat the
  rationale layer as frozen unless a gate finds a defect that changes what the item teaches — a
  limb diagnosing an option it no longer faces, a rationale teaching the opposite of its key, a
  quoted span that is not byte-identical. Those are correctness. A lemma repeated twice in forty
  words is not, and chasing it costs more than it buys.
- **The prose freeze covers the RATIONALE layer. It does not cover the passage.** A grammatical
  error in a passage is not a style wobble: the passage is the thing being tested, and a Swedish
  reading exam whose text has a neuter noun taking common-gender agreement is defective in a way an
  inelegant explanation is not. So: in the rationale layer, repair only what changes what the item
  teaches. In the passage, repair anything a native reader takes as simply wrong — agreement,
  a collocation that is not the language, a pronoun with no reachable antecedent, a verb missing
  the particle that carries its sense. Those are correctness wherever they sit.
- **Change the fewest strings that discharge the finding, and list every changed string.** The
  changed-string list is the audit surface; a round that cannot produce one has not been audited.
- **Sweep the unchanged copy once per round.** Batch22's clearest process finding: every round
  repaired the copy it had just written and never re-read the copy it had not. One unit carried
  three identical paraphrase-then-quote stutters in its first question, untouched through three
  rounds, while the same defect was fixed three times in its second question. Each round reads
  every rationale limb, including the ones it is not editing.
- **Gate-supplied replacement strings are proposals, not instructions.** Screen them like any
  other replacement — against the quote they will precede, against sibling limbs, against the
  bank at n ≥ 5. In batch22 a repair agent correctly rejected three of its grader's strings: two
  recreated the exact stutter they were meant to fix, and one contradicted its own unit's D limb.
  If you reject a prescription, say so and say why. A grader reads the sheets, not the unit.
- **When you rebuild a stem, re-derive EVERY option's refutation against the new stem.** Fewest
  strings does not mean fewest checks. Batch22's tramway question was rebuilt to move a
  world-known fact out of its key; one option was deliberately left untouched because its killing
  span still existed — and the span did still exist, but it no longer refuted, because the old
  stem asked which trouble was worst and the new stem asked how the tramway met winter. An option
  that dies as "a consequence, not the trouble" does not die when the question stops asking for
  the trouble. A rebuilt stem invalidates every refutation in its set until each is re-run.
- **Read every changed span aloud with two sentences either side.** This is what caught a coda
  that contradicted its own opening, a pronoun with no antecedent, and a key rationale that had
  been inverted into teaching the opposite of its key.
- **One `repair_log` entry per round, at TOP LEVEL** — not nested under `generator_meta`. One
  batch22 unit nests it; the digest and sheet tools index the two placements differently. Fix
  before V-FINAL.
- **A metadata-only round proves it is metadata-only**: record the sha256 of the student-facing
  layers before and after and state that they are identical.

## RULE 28 (NEW — when the blind pick lands on the key, the key is the leak)

Batch22's tramway unit took a G-STEM kill in all three rounds. Each round rebuilt the distractors;
each round the blind pick stayed on the same key and the confidence went *up* (≈55 % → ≈45 % →
65–70 %). The diagnosis arrived only in round three: the key stated the canonical, world-known
fact about its subject, so no distractor rewrite could ever hide it.

- **If the same option is the blind pick across two rounds while the distractors change, rebuild
  the KEY, not the distractors.** Keep the key letter; move the key's content to a fact the
  passage states and the world does not supply. Put the canonical fact into a distractor.
- **Distractors are plausible-but-unsupported, never implausible-in-the-world.** The tramway
  unit's tic was a set of options a period-literate reader could eliminate without the passage
  (steel rail worn out by two winters of sanding; a line closed for weeks by one snowfall; a
  curve that shortens the journey). Every one of those is a free elimination. The test: could a
  well-read student who has not seen the passage rule this out? If yes, it is not a distractor.
- **Do not cluster specific numbers and dates in the non-key options.** In the same unit, five
  of the gratuitously precise figures sat in distractors and none in a key. That is a form tell,
  and it is visible from the stems sheet alone.
- **Whole-text / main-idea items: at most ONE per multi-item unit**, and the sibling stems must
  not read as a table of contents. Batch22's arena unit shipped two whole-text items in a
  five-item set and measured a ≈40 % stems-only floor; the tramway unit's four stems together
  reconstructed the subject well enough to support a ≈50 % floor. The floor disclosure
  (`main_idea_sibling_stem_floor`) stays required, and it is now required for the *set*, not only
  for the item: state your own blind estimate from the sibling stems alone.
- **G-STEM runs TWO independent blind legs, and a kill requires both.** G-KEY has had two legs from
  the start and they have agreed on every question of two batches, because the passage determines the
  answer. G-STEM had one leg, and it does not measure the same kind of thing: with the passage
  withheld there is often no determinate answer, so a blind pick is a judgement about which channel
  dominates, and two competent readers legitimately differ. Measured on batch23's identical sheets:
  - mean confidence spread between legs **0.073**, maximum **0.22** — wider than the whole gap
    between a flag and a kill;
  - blind picks identical on only **15 of 22** items;
  - of three single-leg kills, **one** survived the second leg. Repairing on one leg would have
    rebuilt two items that a second reader passed or flagged.
  The gate is nonetheless well-behaved, and the pattern proves it: **every pick disagreement sits at
  low confidence (0.25–0.42), and the legs agree on the pick in every item where either claims a
  channel at 0.5 or above.** It disagrees exactly where it says there is nothing to find. So the
  instrument is sound and the sampling was not. Resolution rule, mirroring `gkey_resolve`: a kill
  needs both legs; a single-leg kill is a flag and is recorded with both figures; where the legs
  differ on a pair floor, report both and treat the higher as the planning figure.
- **A unit's author cannot measure its own blind floor, the estimate is a hypothesis not evidence,
  and the field must name which floor it states.** There are two different quantities and the first
  draft of this rule conflated them, so state the condition or the number means nothing:
  - **No-passage-with-options.** Prompts AND option sets visible, passage hidden. This is what the
    `stems/` sheets carry and therefore the only floor any gate measures. G-STEM's per-unit figure
    is exactly the arithmetic mean of its own per-question blind-pick confidences — verified on all
    seven batch23 units, six matching to the decimal.
  - **Prompts-only.** No options either. **Nothing in the pipeline measures this.** No gate reads a
    prompt without its option set, so a `stems_only_floor` field stating it is unfalsifiable here.
  Measured like-for-like on the one batch23 unit that published both quantities: author 0.36 against
  the gate's 0.49, low by 0.13. The larger gaps quoted when this rule was first written (0.25 against
  0.49, 0.29 against 0.52) compared a prompts-only estimate to a with-options measurement and are not
  evidence of the size of the bias, only of its direction. The direction is real, one-directional in
  every case, and structural: the author knows the passage and cannot un-know it.
  So: keep the estimate, because writing it forces the author to look; name its condition; label it
  an estimate by its author; and never let it stand in for the gate. A lane whose previous unit was
  withdrawn is not fixed by a successor whose author says the floor is low.
- **Retiring a leaking item can raise the floor of the items that remain, and that must be disclosed
  rather than netted off.** Batch23's ELF long retired its whole-text question, which had leaked at
  0.78 — and its prompts-only set floor went UP, from an estimated 0.25 to 0.32, because the retired
  whole-text stem named nothing while its detail replacement names a date and houses being lit. The
  unit disclosed the rise instead of reporting only the closed kill.
- **The cloze lane is the control.** Batch22's cloze unit measured a stems-only floor of exactly
  chance, took zero kills in any round and zero defects from any repair. Contentless gap labels
  leak nothing. Where a lane can carry a cloze, that is the safest item type in the pipeline.

## RULE 29 (NEW — the cross-lane convergence trigger, rewritten)

The batch22 lane table triggered a "major" on a pair *converging at thesis-shape AND coda-type*.
By round three that trigger had inverted: the pair it was drafted for had been separated (1 of 5
shared arc moves, different coda types), while it fired instead on two units that share nothing
but the shape of a generic how-a-familiar-thing-works essay — no investigator, no instrument, no
study, no demoted rival account, no shared name, family, subject, language or n-gram. Three
gates in three rounds reached the same disposition of NOTE by the same reasoning. The trigger,
not the units, was wrong. Replacing it:

- **A convergence is a MAJOR when EITHER (≥ 3 consecutive aligned arc moves AND ≥ 1 shared device)
  OR (≥ 4 shared devices, at any alignment).** Device means one of: a named investigator; an
  instrument; a study or survey; a demoted rival account; a remedy fitted at a measured point.
  The trigger is disjunctive because the conjunctive version, tested against batch22, fired on
  nothing at all: the batch's two maxima sit on *different pairs*. One pair aligned at 5 of 5
  consecutive moves and shared zero devices (two generic personal essays, correctly not a major);
  another shared all five devices and aligned at only 2, and that second pair is plainly the
  batch's closest. A conjunction cannot catch either.
- **A device is a construction the piece REASONS WITH, not a thing it reports on.** This clause was
  missing and its absence reopened a settled ruling. Batch23's register gate read devices off the
  bytes — correctly applying RULE 29's own "write the arc off the bytes" discipline — and found a
  redesign present in a unit that merely *reports* the redesign as history. Present is not the same
  as load-bearing. The test: remove the candidate device and ask whether the piece's argument still
  stands. If the piece still works, it was subject matter. If the argument collapses, it was the
  device. A unit must state, for each device it declares, the sentence whose force depends on it.
  Record a bytes-level inventory of devices *present* alongside the declaration, because the
  difference between the two lists is exactly where a convergence argument will be fought.
- **Segmentation changes the answer, so the arc must be segmented once and declared.** The same two
  units score 3 consecutive aligned moves under one reading and 2 under their own, purely because one
  of them can be cut into five moves two different ways. State your five moves and the sentence each
  begins at; compare against the sibling's declared segmentation, not a re-cut of it.- **Alignment is offset-tolerant.** Compare arcs at the best offset as well as strict ordinal
  position, and report both. The pair above scores 1 on strict ordinal alignment purely because one
  unit folds its mechanism into its opening and runs a move ahead of the other throughout. An
  alignment rule that cannot see a constant offset is measuring formatting, not structure.
- **Coda type is a quota row, not a trigger term.** The quota (RULE 24) stands as written: at most
  two unresolved, at least one concrete image, at least one resolved fact, at least one mid-scene,
  no LÄS coda on `kvar`. Name your slot in `generator_meta`, and name it the same way in every
  field that mentions it — batch22 had one unit whose two fields claimed two different slots.
- **Write the arc off the bytes, not off the label.** The batch22 cross-lane pre-screen compared
  `thesis_shape` strings and missed a 5-of-5 arc alignment, because one unit's label had gone
  stale relative to its own prose. Four of seven units declared the same thesis label while their
  arcs differed; two declared different labels while their arcs matched move for move.
- **The copular epigram is an ELF long/cloze tic. Report its density with the counting rule
  stated; do not quote a bare number.** Batch22 produced two counts of the same four passages that
  disagree by a factor of three (5 / 6 / 3 / 1 in round three, 19 / 14 / 6 / 1 in round four),
  because only the second stated its rule — finite BE as main verb, not followed by a participle,
  with a nominal or adjectival predicate, and existential and bare-locative predicates counted
  separately. The first does not re-derive from any stated rule. A count without its definition is
  not a measurement, and a cap built on one is unenforceable, so no absolute cap is set here.
  Report the density per sentence under the stated rule, and compare it to the authentic ELF
  corpus rather than to a sibling. Batch22's ELF densities under that rule: 0.34, 0.67, 0.31, 0.10
  per sentence.

## CORRECTION — the ELF quotation-punctuation rule, replaced

Batch22 settled on: *a stop goes inside the quotation marks only where the span reproduces a
complete passage sentence terminated at exactly that point AND the citation is colon-introduced.*
Tested two-directionally against batch23 it fails in both directions — 4 violations of the forward
implication and 9 of the converse, with every colon-introduced whole-sentence citation in two units
putting the stop outside. The colon conjunct has no predictive force at all. Worse, read strictly
the converse is vacuous, so a purely confirmatory test reports the rule holding. That is how it
survived a batch.

The rule that governs, **with the clause it was missing**, tested two-directionally over 61 spans:

1. **The author chooses whether the citation includes the passage sentence's terminal stop. State
   the choice and hold it across the unit.** This is the clause the first version lacked, and it is
   where the whole rule turns. Batch23's four ELF units answered it differently without anyone
   noticing: two never include a terminal stop (0 of 44 citations), two include it whenever they
   quote a whole sentence (6 of 17).
2. **If the citation includes the stop, the stop sits inside the quotation marks and terminates the
   host sentence.** 6 of 6 in batch23.
3. **If the citation stops short of it, the stop sits outside.** 55 of 55.
4. **Nothing is added inside the quotation marks that the passage did not have.** 61 of 61.

Read with clause 1 stated, the rule has zero counterexamples. Read without it — taking "cut at a
sentence" to mean merely running to that sentence's last word — it fails on 32 of 61, which is what
an under-determined rule looks like when four authors each resolve it privately. Two blind spots are
also now named: the rule says nothing about where a citation *starts* (one unit opens mid-sentence
and still takes the stop inside) and nothing about whether the *host* sentence has a stop of its own
(one host is terminated only by the borrowed one). Decide both in `generator_meta` and follow it.

## CORRECTION — the attested-stem deadlock, and the tooling that resolves it

Law 5 wants stems phrased the way the real exam phrases them. RULE 24 bars any n>=5 token run a
unit shares with the **synthetic** bank. Those pulled against each other and the anti-clone rule
won — because the exam's standard openings had already been used by earlier synthetic units, so a
new unit screening against the bank sees the exam's own phrasing as a clone of our prior output.

Measured on batch23's first round. Rejected as clones, with their authentic attestation counts:
`what are we told about` **21**, `what can be concluded` **22**, `what is said about the` **13**,
`what is implied about the` **8**. Shipped instead, with their authentic counts: `what do we learn
about` **0**, `what can be inferred about` **0**, `why does` **0**, `what does the essay imply`
**0**. The generators rejected the real forms and invented replacements.

**The corpus says the two sections are not the same problem, so the rule is asymmetric.**

| | stems | top 5-token opening | share using an opening attested 3+ |
|---|---|---|---|
| ELF | 405 | 26x (6.8%) | **51%** |
| LÄS | 540 | 5x (0.9%) | **5%** |

ELF openings repeat: reuse is the register. LÄS openings do not: bespoke is the register, and
pushing a Swedish stem toward a formula makes it *less* authentic, not more.

Binding, and mechanically checkable — the inventory is `gates/attested-stem-openings.json`, derived
from `data/parsed` with its source, selection and normalisation in its own `_method` block:

- **Every ELF stem opens on a form attested at least 3 times.** Run
  `gates/scripts/stem_openings.py --report candidates/*.json`; an `UNATTESTED` line is a finding to
  fix, not a style note. Cloze units are skipped by the tool and exempt by nature — a gap label
  carries no phrasing, which is exactly why that lane measures a stems-only floor at chance.
- **LÄS stems need no attested opening, and its absence is never a finding.** The tool reports
  `bespoke`, which is the correct authentic condition.
- **The n>=5 anti-clone screen runs on the stripped stem, both sections.** Use
  `stem_openings.py --strip` and screen its output: the attested frame is exempt and the stem's
  *content* is screened. This is the carve-out GENERATION.md law 10 already grants M-PLAGIARISM
  ("reusing the stem *form* is fine"); RULE 24 now inherits it explicitly.
- **Regenerate the inventory rather than editing it.** If the parsed corpus grows, rebuild; a
  hand-edited attestation count is a RULE 26 violation like any other.

## A gate has two outputs and only one of them is evidence

A gate writes a verdict file and it reports back to the coordinator. **The verdict file is the
shared artefact; the report is private to the coordinator.** They are not the same set of findings,
and batch23 proved they diverge in ways that matter:

- The distractor gate's recommended rewording for a flagged sentence exists only in its report.
  `grep` over every verdict file finds neither of its two proposed strings. A repair agent told to
  apply it could not attribute it, and correctly flagged it as unverifiable.
- One figure the coordinator described as found by "three gates independently" appears in two
  verdict lines, and in one of those the gate records it as CONSISTENT rather than as a finding.
- Two findings the coordinator attributed to two gates are findings 8 and 9 of a single line.

All three came from the coordinator merging a gate's prose report into a repair prompt while
telling the agent to cite the verdict line. The agent cannot see the report. So:

- **If a finding is not in a `findings` array, it is not a finding.** A gate that wants something
  repaired writes it into the verdict file. Anything that lives only in the report is coordinator
  direction, and a prompt must label it as such — "not in the verdict file; my direction" — so the
  agent knows it cannot verify it and treats it accordingly.
- **Derive repair scope with `gates/scripts/repair_scope.py`**, which reads only the verdict files.
  Anything it does not print for a unit does not belong in that unit's prompt.
- **Never write a count of gates from memory.** `repair_scope.py --unit <id>` prints the gate,
  target, vote and source line for every record. Two findings in one line is one gate.

Measured: seven repair prompts written by hand from notes carried nine attribution errors across
five of them. Every one was caught by the agent receiving it, in each case by reading the verdict
line. None was caught by the coordinator before dispatch.
