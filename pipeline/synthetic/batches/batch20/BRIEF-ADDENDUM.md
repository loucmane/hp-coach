## RULE 11 (NEW — from las-b17-001, demonstrated blind-solvable 4/4):
**No cross-question lexical or conceptual bridges.** After drafting, take
each question's OPTION SET alone (no passage, no stems) and check every
other question's option set for shared content words or paraphrase-level
concept repeats. A word family that appears in one question's KEY and
another question's options (batch17's 'glöd' chain: q2 "glödde kvar" ↔ q3
"släcka glöden" ↔ q4) lets a blind solver corroborate keys across the
sheet — a fresh G-STEM reviewer walked batch17's las-b17-001 to ALL FOUR
keys this way. Mechanical self-check required in NOTES: list every content
lemma appearing in ≥2 questions' options; justify each survivor (function
words and the passage's unavoidable topic word are exempt; mechanism words
are not).

## RULE 12 (NEW — from elf-b17-003): **The stem must not entail any option.**
Read each stem by itself and write down what it gives away. A stem that
semantically entails an option's claim ("the pin the leaf STANDS ON" ⇒
"carries the leaf's weight") hands the blind solver a pick even when it
lands on a distractor — that's a misfire channel we no longer ship
knowingly. Prefer neutral referential stems ("Vad sägs om X?" where X is
named without predicating anything contested about it).

## RULE 13 (NEW — style-tell clustering): never let exactly one option per
question be the qualified / two-factor / hedged one when its siblings are
sweeping — the M-FORM absolutizer family is now COMPLETE (alltid/aldrig/
samtliga/alla/allt/varje/enbart/endast/ingen/inget/inga/helt/omöjligt/
garanterat/ingenting/ingenstans/uteslutande + EN counterparts incl.
nothing, nobody, "no one", nowhere, everyone, everybody, everything) and
G-STEM hunts the residue. Per rule 10: on some questions the KEY is the

# Batch20 supplement (binding, 2026-09-01)

This file is the whole accumulated chain above + this supplement. Where
lists conflict, THIS section's additions extend (never shrink) the
exclusions. RULE 15–20 are binding on batch20 generators and on the gates
that read their output.

## RULE 15 (NEW — from las-b19-003, measured as a PAIR at stage 11):
**In a two-question LÄS set, never pair a mechanism-inventory question with
a stance question over the same hypothesis space.** Measured separately the
set is unremarkable — Q1 alone ≈ 70 % stems-only, Q2 alone ≈ 55–60 %, which
is why every gate and the meta-review filed it at note. Measured as a pair
it reads to **≈ 80 % with the passage unopened**: Q1's options are an
inventory that reprints the essay's hypothesis space, so they NAME the
candidate mechanisms; Q2's options are stances over that same space, so Q2
inherits whatever Q1 discloses and becomes the easier of the two once Q1 has
been read — the reverse of the intended dependency direction. If one
question enumerates candidate mechanisms, **the other must turn on
something outside that enumeration** (a detail, a scope limit, a
method-versus-result contrast — anything whose option field is not the
hypothesis list). State the pair check in NOTES: give the joint stems-only
floor, not two separate per-question floors.

## RULE 16 (NEW — minimum edit distance 2 for every invented name):
**Every coined name must sit at Levenshtein distance ≥ 2 from BOTH (a)
every proper noun already shipped in the bank and (b) its real
gazetteer/surname neighbours — and the one-letter variants must be
enumerated BY HAND.** A fuzzy search engine will not surface the collision:
it silently corrects the query to the real name and returns a clean-looking
zero for the string you asked about. Evidence: **Stintbury ~ Saintbury**
(batch18 — distance 1 from a real Gloucestershire village, same
English-parish domain, and the unit's own note listed Saintbury while
asserting "each at edit distance 2 or more"); **Margit ~ Marit** (batch19 —
distance 1 from a listed given name, compounded because the surname
Torpenius shares the learned `-ius` tail with **Sundelius**, and the shipped
pair is *Marit Sundelius*, so the near-miss lands on both name axes against
one and the same shipped pair). Two further batch19 corrections make the
same point from the other side: Draystow was asserted clear at distance 4
and is at distance 2 from **Drayton** and **Bradstow**; Nabbsworth was
asserted clear and is at distance 2 from **Nailsworth**. In every case the
neighbour set had been *enumerated from the search results* instead of
*computed*. So: compute the distances, do not quote them from a result page;
run the bank screen mechanically over every capitalised token in every
shipped title, passage, prompt and option; and probe one-letter variants
explicitly on the endpoints. The withdrawal of **Tarrowfen** (distance 2
from shipped *Larrowden*, caught only by the fleet gate) is what this rule
costs when it is skipped.

## RULE 17 (NEW — at least one ordinary name per unit):
**No unit may present its coined surnames as an unbroken cluster.** At least
one named figure per unit carries an ordinary, unremarkable name, so the
coined ones have something to measure against. Evidence: two batches in a
row, in ELF, a fresh stage-11 reader pointed at the name-weave and no gate
reacted — **Calverend / Grendisham / Steadgrove / Ockendale** in elf-b19-001
("*harmless to a student, but it is the one place the piece feels
manufactured rather than reported*") and **"Tebbenholt"** in elf-b18-004.
G-REGISTER tests collisions and distances, not TEXTURE, so this is a
generator-side obligation. The batch18/batch19 tactic of an ordinary given
name over a coined surname (Edith Gimberfold, Silas Ludderby) is the cheap
form of it; one wholly ordinary figure is better.

## RULE 18 (NEW — mechanical registry refill):
**The exclusion registry is refilled mechanically from EVERY shipped unit,
never curated from the names that happened to reach adjudication.** Run
`gates/scripts/registry_extract.py <candidates-dir> [...] --exclude-brief
<previous BRIEF-ADDENDUM.md>`, then cross-check the output against each
unit's `generator_meta.originality_note` before curating. Curate one way
only: you may drop ordinary-word noise, you may **never** drop a string that
an originality_note records as a coined name or place. Evidence:
**"Vässlinge"** was invented in batch15, was never adjudicated, therefore
never listed — and both the batch19 generator and G-REGISTER checked
batch19's one-letter neighbour against that list and cleared it in good
faith. The defect was in the register, not in the unit. Note the extractor's
own deliberate blind spot: it reads the student-facing layer only, so a name
that a unit INVENTED but never printed (batch19's lake **"Vässlingen"**,
which exists only in the search log) is caught by the originality_note
cross-check and by nothing else. Both legs are required.

## RULE 19 (NEW — statistics are recomputed, never copied forward):
**Every statistic asserted in `generator_meta` is recomputed on the bytes of
the round that touches it.** No figure survives a repair round by being
carried over; if a round edits a file, every count that describes that file
is re-derived from the new bytes before the round closes. Evidence — three
separate falsified figures across batch18/19, each falsified in a different
way: (1) elf-b18-002's **whole-file em-dash count** was falsified *twice*,
both times by the very repairs that changed the file (VF-04 after

whole-file count is asserted at all; (2) elf-b19-001's **hedge-balance
count** moved from 1-of-5 to 2-of-5 "by re-labelling rather than by any byte
change on that axis" — the number improved without anything in the unit

lower than it is; (3) elf-b19-004's **key-distribution figure**, supplied by
