### Design

**1. Provenance (server-side, never client-trusted)** — `worker/src/lib/provenance.ts`.
- **authentic:**
  - the exam is one of the 27 sittings of `app/public/data/_index.json`, pinned by a test;
  - the provpass is `verb1`/`verb2` with ORD, LÄS (legacy LAS accepted), MEK or ELF, or `kvant1`/`kvant2` with XYZ, KVA, NOG or DTK;
  - the number is three ASCII digits.
  - All 4320 bank qids classify authentic.
- **synthetic:** the qid is in the bundled registry and agrees with its own unit, revision and section. `itemRevision` is the unit revision (las-b7-002 → 2).
- **unknown:** anything else. That includes retired units (`p5-elf-b14-002-…`), revoked revisions (`p5-las-b7-002-r1-…`), sittings the bank does not hold, seed or test ids and malformed qids. An unknown answer is stored and never assessed.

**2. Registry.**
- The qid list is exactly what an approved export would ship.
- Framework ids come only from P5 explanation shards that pass the export's own explanation gate. That gate checks coverage, schema, distractors, that the framework id belongs to the question's own section in `frameworks/*.json`, internal labels, rationale leaks, learner lint and canonical bytes.
- The exporter refuses on any of these:
  - a shard qid outside the registry;
  - a shard name that is not a valid release;
  - a symlinked shard;
  - two shards that disagree on a framework id.
- The registry binds the roster, `RETIRED.json` and the shards by sha256. A stale registry fails CI through `test_the_committed_registry_is_the_current_build`. Today only `p5-pilot.json` exists, which gives 14 framework ids; PR 2b shards are picked up when the registry is regenerated.

**3. Persistence and backfill.**
- Every provenance column defaults to the fail-closed value.
- **Backfill rule** (0013), for rows that predate the columns: `authentic` exactly when the qid matches the authentic registry, else `unknown`. Nothing is backfilled `synthetic`, because no P5 question was served before this PR. `item_revision` stays null.
- The backfill only promotes `unknown` rows, so it is safe to re-run.
- `drizzle-kit`'s own differ (`generateSQLiteMigration`) finds nothing between the newest snapshot and `schema.ts`.

**4. What counts where (Amendment 1 E).**

| Number | Sources |
|---|---|
| `/stats` `accuracy7d`; `bySection` score / trend / confidence inputs (`attempts7d` … `correct90d`), `avgTimeMs`, `lastAttemptedAt`; `weekly` | authentic + synthetic |
| `/stats` attempt counts, `timeMsToday`, streak, `attemptsDaily`, `bySection.attemptsToday` (practice effort) | every answer, as before |
| Elo fit (`user_ability`, `item_stats`) | authentic + synthetic; unknown skipped, watermark still advances |
| `/item-stats` | authentic + synthetic rows; `unknown` rows never served |
| mastery / `framework_progress` | authentic: every client tag (unchanged). Synthetic: only the registry's framework id for that qid, and only if the client tagged it. Unknown: nothing. |
| Provpass result (client-computed) | every presented question, P5 included; basis stored server-side |
| hot-trap / top-trap counts (app) | authentic unchanged; P5 only when the explanation's framework id is a framework of the question's section |

**5. `estimateBasis`.**
- The shape is `{ authentic, synthetic, calibrated }`, with `calibrated = (synthetic === 0)`. It appears on:
  - `/stats` `bySection[s]` (the 90d score window);
  - each `/stats` `weekly` bucket;
  - `/me/ability[s]`, as `attempts − synthetic_attempts` and `synthetic_attempts`.
- A Provpass `mock_results.estimate_basis` also carries `unknown` and `perSection`.
  - It is calibrated only when the plan has no synthetic and no unknown qid. The client-computed score includes unknown qids and the server cannot take them out.
  - Rows from before this PR, or from a session without a stored plan, have `null`.
- `/item-stats` lists `uncalibrated` qids.
- App helpers for PR 4: `sectionBasis`, `projectionBasis` (verbal, quant and total, combining the sections that have a score), `weeklyBasis`, `normedEstimate` and `isCalibrated`. Every new field is optional on the client, and an absent basis reads as calibrated: an older worker, or pre-P5 data that rests on authentic answers only.

**6. Fit: the interim, uncalibrated method** (documented in the `worker/src/lib/fit.ts` header).
- **Authentic answers:** fitted exactly as before. The arithmetic and order of operations are unchanged.
- **Synthetic answers:** P5 items have no UHR normering or calibrated difficulty, so the user side plays them at the section **anchor**. The anchor is the mean difficulty of the section's authentic items with at least one fitted attempt, or 0 (the scale's neutral prior) when there are none.
  - The legacy LAS spelling is pooled under LÄS.
  - The item side still learns the P5 item's own difficulty against the user's ability (guess floor, K schedule, replay damping), but keeps it apart: `item_stats.source = 'synthetic'`, and it never enters any anchor.
  - `user_ability.synthetic_attempts` counts the synthetic answers. With the stored source and item revision on every attempt, a later recalibration can tell which contributions to recompute.
- **Determinism.**
  - The anchor is read from the live ratings, the same state objects as the item cache. It is summed in qid order and recomputed whenever an authentic item of its section moves; it is never carried between runs.
  - The pool is loaded only when a run meets its first synthetic answer, so an authentic-only run does exactly the queries it did before.
  - A mixed history fitted in 2–4 incremental runs lands byte-for-byte on the ratings of one run (4 seeded trials).
- **Stability.** Ratings stay finite and inside ±800 over a 600-answer synthetic-only history. An empty anchor is 0, never NaN.

**7. Normering.** `normedEstimate(sitting, half, correct, presented, basis)` returns exactly `normedScore`'s `{score, derived}` for the pass's raw performance, whatever its source, plus `calibrated` from the basis.
